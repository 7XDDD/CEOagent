## Step 1：系统全景

### 1.1 系统定位

一句话：**面向公司管理层与财务/销售条线的"合同—预算—执行—报表"一体化财务预算系统**，以"合同 + 里程碑"为唯一业务源头，向下推算合同额预算、收入预算、税费预算、回款预算，再向上汇总为利润预算、现金流预算、达成率、应收账款与经营驾驶舱。

- **给谁用**：公司管理层（驾驶舱、达成率、预测对比）、财务（预算编制、预算汇总、利润/现金流预算、应收）、销售/商务（合同与里程碑维护）、系统管理员（用户/角色/权限/日志）。
- **解决什么问题**：把散落在合同与里程碑中的金额、时间、税率，按统一口径固化为可版本化、可锁定的年度/滚动/调整预算，并与实际执行数据对比。
- **核心价值**：口径统一（一套税率与归属月规则）、可追溯（版本 + 快照）、可对比（预算 vs 实际）、可管控（锁定 + 权限）。

### 1.4 角色 × 模块 权限矩阵

系统采用 **RBAC + 端点级 `@PreAuthorize` + 前端菜单/路由/按钮三级过滤**。源码中不存在角色初始数据（无 SQL 种子），下表按"权限码语义 + 代码事实"归纳，具体角色绑定需查库。

| 角色（推断） | 可访问模块 | 权限特征 | 依据 |
|---|---|---|---|
| `SUPER_ADMIN` | 全部 | 带 `@PreAuthorize` 的业务端点几乎都带 `or hasRole('SUPER_ADMIN')`（权限树的 `tree`/`list-all` 仅要求登录）；前端 `isSuperAdmin` 直接放行 | `SecurityConfig`、各 Controller、`stores/user.js:44-57` |
| 系统管理员 | 系统管理全部 | 用户/角色/权限/字典/日志的 view/edit/create/delete/reset-pwd/assign-* | `system/*Controller` 权限码 |
| 财务/预算管理员 | 基础数据 + 业务数据 + 预算管理 + 报表 | `base:*`、`business:*`、`budget:*`、`report:*`；预算计算需 `budget:edit` 或 `budget:calculate` | 各 Controller |
| 销售/商务 | 合同管理 + 报表只读 | `contract:view/add/edit/status/copy/import/export`；报表 `*:view` | `contract/ContractController` |
| 只读/管理层 | 驾驶舱 + 报表 | `/dashboard/**` 无 `@PreAuthorize`（仅需登录）；`report:*:view` | `DashboardController` |
| 普通员工 | 个人中心 + 被授权菜单 | 仅 `profile` 始终放行；其余菜单按 `permissions` 过滤 | `router/index.js:168-183`、`layouts/index.vue:333-341` |

**前端权限判定细节（重要）**：
- `hasPermission(p)`：`SUPER_ADMIN` 直接 true；否则 `permissions` 包含 `p`，或存在以 `p:` / `p.` 开头的权限码（前缀继承）。见 `fs-front/src/stores/user.js:46-57`。
- 路由守卫：未登录 → `/login`；已登录但未拉取权限 → `GET /auth/info`；无任何权限 → `/403`；无该路由权限 → `/403`。见 `fs-front/src/router/index.js:191-245`。
- 菜单：`allMenuList` 静态定义后按 `permission` 递归过滤，父菜单仅剩子项时保留。见 `fs-front/src/layouts/index.vue:263-345`。
- 按钮：各页面用 `computed(() => userStore.hasPermission('xxx'))` + `v-if`；`v-permission` 指令虽已注册（`main.js:21`）但全站未使用。

## 模块 A：认证与个人中心

### 业务目标

|---|---|---|---|
| `/login` | `views/login/index.vue` | 匿名 | 用户名/密码/图形验证码登录、记住用户名、忘记密码（前端占位） |

### 逐页深潜

#### 页面：登录（路由：`/login`）

**业务理解：**
- **触发场景**：未登录访问任意受保护页面，守卫重定向到 `/login?redirect=原路径`；Token 过期被 401 拦截后也会回到这里。
- **可交互元素**：用户名/工号输入、密码、4 位图形验证码（点击刷新）、"记住我"、登录按钮、"忘记密码"链接。
- **核心流程**：页面加载 `GET /auth/captcha-key` 获取 `captchaKey + base64 图片` → 用户输入 → `POST /auth/login`（username/password/captchaKey/captchaCode）→ 成功后 `userStore.setUser(data)`（持久化 token/userId/username/realName/avatar/tokenIssuedAt）→ 若有密码到期提醒先弹框 → 解析 `redirect`（必须本人有路由权限）否则跳第一个有权限菜单，全无权限跳 `/403`。
- **边界条件**：
  - 验证码未加载完成点登录 → "验证码正在加载，请稍候"。
  - 验证码错误/过期 → 后端 1004，日志记 `CAPTCHA_INVALID`，前端刷新验证码。
  - 账号禁用 → 1003；连续失败 5 次锁定 30 分钟 → 1003 并提示剩余分钟；密码错误统一提示"用户名或密码错误"（不暴露用户是否存在）。
  - 登录成功但无任何权限 → 落 `/403`。
  - 后端 502/断网 → 不清 token（`request.js` 仅 401 清登录态）。

**数据流转：**

| # | 功能点 | 数据来源 | 转换/校验 | 去向 | 关联代码位置 |
|---|---|---|---|---|---|
| 1 | 加载验证码 | `GET /auth/captcha-key` → `{captchaKey, captchaImage}` | Hutool 生成 4 位线段验证码；服务端 `ConcurrentHashMap` 存 key→code，TTL 5 分钟；返回 Base64 | `el-image` 展示；`captchaKey` 存入组件状态 | `controller/CaptchaController.java:72-86`、`views/login/index.vue:254-266` |
| 2 | 提交登录 | 表单 + captchaKey | 前端校验：用户名 2-30 位字母/数字/下划线/横杠；密码必填；验证码 4 位 | `POST /api/auth/login` | `views/login/index.vue:268-343` |
| 3 | 验证码校验 | 内存 Map | 一次性消费（`remove`）；超时或不存在即失败 | 失败写 `sys_login_log`（CAPTCHA_INVALID） | `UserService.login:66-72` |
| 4 | 用户与状态校验 | `sys_user`（按 username 或 employee_no） | 不存在→1001；status=0→1003；锁定未到期→1003 并算剩余分钟 | 失败写 `sys_login_log` | `UserService.login:74-111` |

| 9 | 落地页解析 | 前端 `permissions` | `redirect` 必须有权限，否则第一个有权限菜单，否则 `/403` | `router.push` | `views/login/index.vue:318-340`、`router/index.js:178-183` |

#### 页面：个人中心（路由：`/profile`）

**业务理解：**
- **触发场景**：右上角头像菜单"个人中心"；密码到期提醒的"去修改密码"；`PasswordExpiredFilter` 拦截后前端弹框跳转（`?tab=password`）。
- **可交互元素**：两个 Tab（个人信息 / 修改密码）；信息项：姓名、工号、邮箱、手机、职位；密码项：原密码、新密码、确认密码；只读区：角色、用户类型、登录次数、最近登录 IP/时间、密码剩余天数；"退出登录"。
- **核心流程**：`GET /auth/info` 拉全量资料 → `PUT /auth/profile` 保存资料 → `POST /auth/change-password` 改密（成功后应重新登录）。
- **边界条件**：邮箱格式、手机号格式前端校验；新密码 8-20 位且必须含字母+数字+特殊字符；两次密码不一致拦截；原密码错误返回明确提示；密码过期状态下除白名单接口外全部 403。

|---|---|---|---|---|---|
| 1 | 加载资料 | `GET /auth/info` | 后端聚合 `sys_user` + 角色 + 权限（含父级）+ 登录次数 + 密码到期信息 | 表单/展示区 | `UserService.getCurrentUserInfo:214-258` |
| 2 | 保存资料 | 表单 | 只允许 realName/employeeNo/email/phone/position | `PUT /auth/profile` → `sys_user` | `AuthController:118-130`、`UserService.updateProfile:286-310` |

| 4 | 密码过期拦截 | `passwordLastUpdateTime` | 超过 90 天 → 除 `/auth/login`、`/auth/logout`、`/auth/info`、`/auth/change-password`、`/auth/profile`、`/captcha`、文档外全部 403 "您的密码已过期" | 前端统一弹不可关闭对话框 → 改密页 | `security/PasswordExpiredFilter.java:77-104`、`utils/request.js:26-45` |

#### 页面：403 / 404

- `/403`：无权限时由守卫跳转；页面提供"返回首页/重新登录"。
- `/404`：`/:pathMatch(.*)*` 兜底；提示页面不存在。
- 边界：`/403` 在守卫中 `requiresAuth=false`，不会被权限再次拦截，避免死循环。

### 逐页深潜

#### 页面：经营驾驶舱（路由：`/home2`）

**业务理解：**
- **触发场景**：登录后默认落地页（`menuLeafOrder` 第一项）；点击左上角"首页"。
- **页面结构（自上而下）**：
  1. 标题栏：年度 + "管理层视图" + 数据截至日期 + 手动刷新。
  2. **四大 KPI**：累计签单、累计收入、累计回款（各带年度目标、完成率、年度缺口）、累计净利润（1~上月，取利润预算"五、净利润"）。
  3. **应收风险预警条**：应收余额、逾期金额、逾期客户数 → 点击跳 `/report/receivable`。
  4. **经营性现金流**：月度/累计/年度三档切换；流入、流出、净流量、ECharts 柱线图；"距年底还有 N 天"。
  5. **应收账款 TOP5**：客户、合同笔数、金额、占比。
  6. **成本费用结构**：环形图 + 图例（取利润预算口径，1~上月累计）。
  7. **本月收入预测 TOP5 / 回款预测 TOP5**：预测/已确认（已回）切换；"漏预测"标记（无预测但已确认/已回款）。

## 模块 E：业务数据

### 业务目标

沉淀"钱从哪来、花到哪去、什么时候到账"的三类业务事实：

1. **合同与里程碑**（`bus_contract` / `bus_contract_milestone`）：唯一的一手业务数据，预算计算的全部输入。
2. **营业外收入 / 成本 / 现金流收支数据**（`bud_revenue_budget` / `bud_cost_budget` / `bud_cashflow_data`）：合同之外的"手工填报数"，按科目树 + 组织 + 月份录入，供利润预算和现金流预算使用。
3. 通过 Excel 批量导入降低录入成本。

不做会导致：利润预算只剩合同收入，费用/营业外收支缺失；现金流预算只剩经营性合同回款，投资/筹资活动缺失。

##### 预算计算引擎拆解（本系统最核心逻辑）

**统一前置**：
- 金额单位：数据库存 **元**，接口展示层转 **万元**（`/10000`，多数保留 6 位）。
- 归属月：收入/税费=开票月；回款=回款月；合同额=签约月。
- 税率解析（`TaxRateService.resolveRates`）：期间税率表（生效日≤归属日≤失效日，取生效日最大）→ 合同类型默认税率 → 系统默认 13%/12%。
- 期间：`bud_budget_period` 必须存在 12 条 MONTHLY + 4 条 QUARTERLY；否则报错。
- 计算前清空：该版本四科目的 `sheet/line/period_amount` 与三张快照全部**物理删除**（非逻辑删除），保证幂等。

**科目 101 合同额预算**
- 合同范围（`findForContractBudget`）：`deleted=0`、`status<>'CANCELED'`，且 (签约日在本财年) 或 (无签约日且预计签约日在本财年)。
- 每份合同生成 1 张 Sheet + 1 条 SIGN 明细行；归属月=签约月，无则预计签约月，再无则 1 月（公式文本注明"依据默认"）。
- 金额=合同金额（元）；期间金额 `amountType=ORIGINAL`，`timeOffsetMonths=0`。
- **不生成**存量/增量、产品线、合计等汇总行。

**科目 102 收入预算**
- 合同范围（`findForRevenueBudget`）：未取消，且排除"已完成且完成时间早于财年 1 月 1 日"的历史合同。
- 逐里程碑：金额=里程碑金额；为空则 `合同额×收款比例`。
- 开票基准日：已开票取实际开票日（`actual_date`，空则 `actual_invoice_year/actual_month`）；未开票取预测日（`forecast_date`，空则预测年月）→ 计划日 → 计划年月。
- **去税**：`收入 = 含税金额 / (1 + 增值税率)`；归属月=开票月；不在本财年的里程碑跳过。
- 每份合同 1 张 Sheet + N 条明细；整张合计为 0 则不生成。

**科目 103 税费预算**
- 合同范围（`findForTaxBudget`）：所有未取消合同（不限签约年）。
- 公式：`收入 = 金额/(1+税率)`；`增值税 = 收入×税率`；`附加税 = 增值税×附加税率`；**预算金额只取附加税**。
- 归属月=开票月；`amountType=ORIGINAL`，`timeOffsetMonths=1`（仅元数据，不改变归属月）。
- 每份合同 1 张 Sheet + N 条明细；合计为 0 不生成。
- ⚠ 与 `/budget/overview` 页面提示"税费预算（增值税+附加税，延后1月）"**不一致**：代码未含增值税本体、也未延后归属。→ `[待确认: 以哪个口径为准]`

**科目 201 回款预算**
- 合同范围：与 103 相同（`findForTaxBudget`），目的是覆盖"上年末开票、本年回款"的合同。
- 逐里程碑取回款日与金额，优先级：
  1. `actual_payment_date` 非空 → 实际回款，金额=`actual_amount` → `expected_payment_amount` → 里程碑金额；
  2. `expected_payment_date` 非空 → 预计回款，金额=`expected_payment_amount` → 里程碑金额；
  3. 否则 → 开票基准日 + 客户回款偏移月（`sys_customer.payment_offset_months`，默认 1），金额=`expected_payment_amount` → 里程碑金额。
- 只保留回款年=本财年的里程碑；归属月=回款月；`amountType=ORIGINAL`，`timeOffsetMonths=0`。
- 每份合同 1 张 Sheet + N 条明细；合计为 0 不生成。

**汇总行（仅 102/103/201）**
- 生成三类汇总 Sheet（`is_summary_row=1`，`contract_id` 用负数占位）：
  1. `存量/增量小计: STOCK|INCREMENT`
  2. `产品线小计: <productLine>`
  3. `<科目名> 合计`

#### 页面：订收回达成率（路由：`/report/achievement`）

**业务理解：**
- **触发场景**：月度/季度经营会；对比"目标 vs 实际"；看缺口在哪个月。

  - **KPI**：年度达成率=全年实际/全年目标；累计达成率=截止月累计实际/累计目标；年度缺口=目标-实际；累计缺口同理；分母 0 返回 0。
- **边界条件**：无目标版本 → 目标全 0/空，达成率 0；实际 > 目标 → 缺口为负（超额）；截止月后实际强制 0，避免"未来数据"污染。

- **核心口径**：
  - **预测**：取对应期间的预算（101 签单 / 102 收入 / 201 回款）按合同汇总，按所选期间月份累加；不同期间类型使用不同版本：月→当月最新版本；季→每月滚动版本；半年→H1/H2 版本；年→年度版本。
  - **实际签单**：签约日在期间内按月汇总合同额（含税）。
  - **实际收入**：已开票里程碑，按实际开票日归属，去税。
  - **实际回款**：里程碑 `actual_payment_date`，含税不去税。
  - **偏差**=实际-预测；**偏差率**=偏差/|预测|×100（预测 0 且实际非 0 时显示"-"）。
- **边界条件**：只保留期间内有预测或实际（非 0）的合同；预测版本缺失则该合同无预测；导出 3 个 Sheet。

**实体关系要点：**
- `Contract` 与 `ContractMilestone` 是 1:N；所有预算/报表的"实际数"几乎都来自里程碑，而不是合同汇总字段。
- `BudgetVersion` 是预算的"时间切片"：同一财年可有多个版本，但 `is_active=1` 只有一个；`is_locked=1` 阻止重算；`is_finalized=1` 仅 ADJUST 使用，作为 7-12 月达成率目标。
- `BudgetSheet` 是"合同 × 科目 × 版本"的预算单；汇总行也用同一张表（`is_summary_row=1`），通过 `contract_id` 负数区分。

- 三张快照是"计算当时的合同/里程碑/税率"的不可变副本，支持"按快照重算"和审计。
- 业务数据三表（收入/成本/现金流）用 `version_id + data_version` 双版本：`version_id` 关联预算版本，`data_version` 是同一版本内的数据批次，利润/现金流预算只取**最大 dataVersion**。

### 3.2 跨模块数据流链路（选 3 条最长链）

#### 链路 1：合同 → 预算 → 汇总 → 达成率（主链）

```

   │
   ▼
[业务] 合同管理：bus_contract（合同额/签约日/状态）

   ├─ 101 合同额：合同范围=本年签约或本年预计签约；月份=签约月/预计签约月/默认1月
   ├─ 102 收入：未取消且非上年完成；逐里程碑；开票月；去税=金额/(1+税率)
   ├─ 103 税费：全部未取消合同；附加税=收入×税率×附加税率；开票月
   ├─ 201 回款：全部未取消合同；实际→预计→开票日+客户偏移月；回款月
   ├─ 汇总行：存量/增量、产品线、合计（仅 102/103/201）
   └─ 快照：合同/里程碑/税率
   │
   ▼

   │
   ├─> [页面] /budget/sheet：12 月 + 4 季 + 明细 + 导出
   ├─> [页面] /budget/overview：四科目卡片 + 月度对比 + 多维透视
   ├─> [报表] /report/achievement：101/102/201 作为目标，合同/里程碑实际作为实际

   │
   ▼

```

### 3.3 权限链路总览

```

        ├─ 白名单：/auth/login|logout|info|change-password|profile、/captcha、/actuator、文档
        └─ 密码过期 → 403 "您的密码已过期"

③ 端点级鉴权（Spring Security @PreAuthorize）
   hasAuthority('xxx') or hasRole('SUPER_ADMIN')
   ├─ 无权限 → RestAccessDeniedHandler → 403 JSON
   └─ 未认证 → RestAuthenticationEntryPoint → 401 JSON

④ 前端
   ├─ 路由守卫：无 token → /login；无任何权限 → /403；无该路由权限 → /403
   ├─ 菜单：allMenuList 按 permission 递归过滤
   ├─ 按钮：computed + v-if（hasPermission）
   └─ 请求拦截：401 → 清 token + 跳登录；403 密码过期 → 不可关闭弹框 → 改密页
```

### 3.6 代码质量与实现观察（非需求，但影响可维护性）

1. **超大类**：`BudgetCalculateServiceImpl` 1789 行、`DashboardServiceImpl` 2039 行、`ProfitBudgetServiceImpl`/`CashFlowBudgetServiceImpl` 均超千行；计算逻辑与展示逻辑混杂，建议拆分"取数/计算/组装"三层。
2. **重复代码**：102/103/201 三段合同循环高度相似（Sheet 字段赋值重复 4 次），税率快照构建在 `calcMilestone` 与 `calcRepaymentMilestone` 中重复。
3. **硬编码**：科目 ID 1/2/3/4、编码 101/102/103/201、默认税率 0.13/0.12、现金流大类 01-05、利润预算科目中文关键字、`catalogId=1L..4L` 均硬编码；`sys_budget_catalog` 未使用。
4. **死代码/死模型**：`DictItem`、`ImportLog`、`BudgetCatalog`、`BudgetSummary`、`BudgetAuditLog`、`v-permission` 指令、`/home` 页面、`BaseController` 通用 CRUD 部分方法被子类覆盖但未删除。
5. **注释与实现不一致**：`/budget/overview` 提示"税费预算（增值税+附加税，延后1月）" vs 代码只算附加税且归属开票月；`BudgetCalculateServiceImpl` 中 `timeOffsetMonths=1` 与实际归属月不一致。
6. **空异常吞掉**：多处 `catch (Exception ignored) {}`（利润预算公司名、税率加载、汇总统计），出错时页面显示 0 而非报错，排障困难。
7. **N+1/全量加载**：利润/现金流预算把公司全部 `CostBudget/RevenueBudget/CashFlowData` 一次性 `selectList` 后在内存过滤年度/版本/组织；数据量大时内存与耗时风险。
8. **无测试**：核心计算引擎（税率、去税、回款偏移、汇总、快照重算）无任何单测，回归风险高。
9. **事务边界**：预算计算整个方法一个事务，包含数十次 insert/update；若中途失败回滚，但耗时可能触发锁等待/超时。
10. **日志**：计算过程有统计日志，但缺少"每份合同/每条里程碑跳过原因"的结构化记录，出错时难以定位是哪条数据。

## 结语

这套系统的"骨架"是清晰的：**合同与里程碑是唯一事实源，预算版本是时间切片，四科目预算 + 三张快照保证可重算与可审计，报表与驾驶舱统一从预算期间金额取数**。真正的复杂度集中在 `BudgetCalculateServiceImpl` 的四段计算与口径（去税、税率优先级、回款偏移、存量增量、汇总行），以及利润/现金流预算的"实际+预算混合"。

上线前建议优先确认 6 件事：
1. `bud_budget_period` 的初始化方式（否则预算算不出来）；
2. 权限码双轨与角色实际授权（否则菜单可见但接口 403，或反之）；
3. 税费口径（附加税 vs 增值税+附加税、是否延后 1 月）；
4. 多租户数据隔离（客户/类型/组织/公司的 `list/all`）；
5. 应收快照的月末操作规范（否则历史报表为空）；
6. 明文数据库口令与 JWT 密钥的轮换。

以上 6 项均已在 §3.5 标注为 `[待确认]`，需要业务方或 DBA 提供信息后才能给出最终结论。
