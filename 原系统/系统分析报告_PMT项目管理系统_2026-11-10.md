## 0. 结论速览（TL;DR）

1. **系统本质**：这不是通用项目管理工具，而是**"项目 → 项目成员 → 周工时 → 多级审批 → 锁定 → 按天结算"**的工时结算中台，财务结算与人力外包结算味道很重；项目/合同/发票/回款只是配套主数据。
2. **真正跑通的主链路只有一条**：`项目成员维护（或工时计划导入自动生成成员） → 我的工时按周按项目填报 → 按项目路由审批流（或签/会签） → 审批通过 → PM 锁定 → 财务按批次按天结算 → 取消结算`。其余模块大多围绕这条链路提供主数据、校验和报表。
3. **权限是"三层叠加"**：JWT 内权限码（按钮/接口）+ 路由 meta 权限（页面）+ `pmt_data_permission / pmt_project_manager` 项目数据域（能看哪些项目、哪些人的数据）。三者不一致时会出现"菜单能进但接口 403"或"有按钮但看不到数据"。
4. **审批引擎已产品化，但有明显未完成项**：支持"项目 > 部门 > 组织 > 全局"四级流程绑定、指定用户、或签/会签、通过/驳回回写业务状态、PM 主管特殊审批链；但**直属上级、部门负责人两类审批人解析器是 TODO，永远返回空**，前端也只开放"指定用户"。
5. **存在一批"半成品/孤儿"功能**：合同、发票、回款、成本 4 个财务页面菜单被注释隐藏，且前端字段与后端实体不一致；物料、审批旧页、项目模板页面没有路由；人力工时预算前后端权限码不一致。这些应视为**未上线/待重构**，不能按"可用功能"对外承诺。

**核心闭环（一句话版）**

```
HR/手工主数据 → 项目+成员(投入占比/时间段/工时性质)
      → 周工时填报(按项目拆单) → 异常检测 → 审批实例(流程路由+或签/会签)
      → APPROVED → 锁定(仅结算性质) → 结算批次(按天) → SETTLED
      → 看板/执行状态/结算统计反哺管理
```

# Step 1 系统全景

## 1.1 系统定位

- **给谁用**：项目经理（PM）、项目成员/普通员工、财务结算人员、系统管理员；另有移动端给员工填报与审批人处理待办。
- **解决什么问题**：把"人天/工时"从填报、审批、锁定到结算做成可追溯闭环，同时用项目/客户/合同/预算主数据把工时挂到可结算对象上。
- **核心价值**：① 周工时按项目独立成单、独立审批；② 审批链可按项目配置；③ 锁定与结算分离，保证财务口径；④ 异常（请假冲突、非工作日、工时不足）前置暴露。
- **不做什么（现状）**：没有任务/看板/甘特等项目执行管理；没有真正的合同-发票-回款联动（页面未启用）；没有附件/文件上传能力（只有 Excel 导入导出）。

## 1.4 角色 × 模块 权限矩阵

角色来源：`RolePermissionPresets`（后端兜底）与 `front/src/stores/user.js` 的 `permissionMap`（前端映射）。`SUPER_ADMIN` / `PMT_ADMIN` 在前后端均短路放行；`userId=1` 在后端也被视为管理员。

| 角色（code） | 可访问模块 | 权限特征 |
|---|---|---|
| `PMT_ADMIN` / `SUPER_ADMIN` | 全部 | 全权限；`PermissionChecker.isAdmin()` 直接 true；数据权限返回 null（全量） |
| `PMT_PM`（项目经理） | PM 看板、基础数据 6 项、项目信息/里程碑/物料、工时计划、执行状态、我的工时、工时审批、工时管理、结算查看/结算、审批实例、审批流程（含增删改/启停） | 近似"项目域管理员"，但项目数据仍受显式授权约束（非成员也可被授权） |
| `PMT_MANAGER` | 同 `PMT_PM` | 代码中 `MANAGER = PM`，完全等同 |
| `PMT_FINANCE` | 仅结算管理 + 工时列表只读 + 结算动作 | 严格最小集：不含项目/客户/看板/我的工时/工时管理；如需报工时需叠加 `PMT_EMPLOYEE` |
| `PMT_MEMBER` | 我参与的项目、我的工时、里程碑/物料只读、工时计划/执行只读 | `pmt:project:my` 不等于 `pmt:project:view`，不会放大成全公司项目列表 |
| `PMT_EMPLOYEE` | 仅我的工时 | 预留角色，适合纯填报员工 |

> 权限码采用 `pmt:<模块>:<动作>`；后端 `PermissionChecker.matches()` 仅支持**精确匹配**与**单层通配** `pmt:module:*`，**不支持父级包含**（`pmt:settlement` 不自动包含 `pmt:settlement:view`）。前端 `hasPermission` 已同步该语义，并在注释中明确说明。

## 2.1 认证、账号与权限域

### 业务目标

让正确的人以正确身份进入系统，并把"能否看到页面 / 能否调用接口 / 能看到哪些项目的数据"三层控制串起来。不做会导致越权查看或结算口径失控。

### 逐页深潜

#### 页面：登录（`/login`）

**业务理解**
- 触发场景：未登录访问任意受保护路由，守卫带 `redirect` 跳到登录页。
- 交互元素：用户名/工号输入、密码输入（回车提交）、登录按钮。
- 核心流程：提交 → 后端校验账号状态/锁定/密码 → 返回 `token + userInfo + needChangePassword` → 前端 `setUser()` 转换权限 → `getDefaultRoute()` 选首个有权限页面 → 跳转。

### 权限链路（四层）

| 层 | 位置 | 判定内容 | 失败表现 |
|---|---|---|---|
| L1 登录态 | `router.beforeEach` | 是否有 token；`requiresAuth` | 跳 `/login?redirect=` |
| L2 系统/页面 | `meta.system` + `meta.permission` | `hasSystemAccess`（权限前缀 `pmt:`）+ `hasPermission(meta.permission)` | 跳 `/403` |
| L3 接口 | 后端 `@PreAuthorize("@permissionChecker.hasPermission('...')")` | JWT 权限码精确/通配匹配；admin 短路 | HTTP/业务码 403 |
| L4 数据域 | `DataScopeServiceImpl` + Mapper 条件 | 显式项目授权（`pmt_data_permission` 用户/角色 + `pmt_project_manager`）；`project_id=0` = 全部项目 | 列表为空或 403/业务异常 |

**数据域规则（关键）**
- 项目可见性**只认显式授权**：数据权限弹窗勾选、角色授权、`pmt_project_manager` 的 `can_view_all/can_edit/can_approve`；**项目成员身份本身不再自动派生项目可见性**（成员填报走 `/projects/my` 独立链路）。
- `project_id=0` + 对应动作列=1 → "全部项目（含未来新增）"总开关，`getAnyAccessibleProjectIds()` 返回 `null`（全量）。
- `PMT_ADMIN` / `userId=1` → 全量；但"工时管理/工时审批"的严格数据域（strictApprovalScope）**刻意不做超管放大、也不认全局总开关**，只认具体项目授权。
- 客观结果：新项目默认对非 admin 不可见，必须在用户管理-数据权限里勾选；这是本系统最常见的"看不到项目/工时为 0"根因。

## 2.2 工时域（系统核心）

### 业务目标

让员工按"周 × 项目"填报每天工时，按项目独立生成工时单并走各自审批流；审批通过后由 PM 锁定、财务结算；全过程留下审批与异常痕迹。不做则无法核算人天成本与外包结算。

### 页面/路由清单

| 路由 | 页面组件 | 允许角色 | 一句话功能 |
|---|---|---|---|
| `/pmt/my-timesheet` | `views/pmt/my-timesheet/index.vue` | 有 `pmt:my-timesheet:view` | 周工时填报、我的工时单、我的加班 |
| `/m/timesheet` | `views/pmt/mobile/timesheet.vue` | 移动端登录用户 | 移动填报/提交/撤回/查看审批链/我的加班 |
| `/pmt/timesheet` | `views/pmt/timesheet/index.vue` | `pmt:approval:view` | 待我审批/我已审批、单条/批量通过驳回 |
| `/m/approval` | `views/pmt/mobile/approval.vue` | `pmt:approval:view` | 移动审批待办 |
| `/pmt/timesheet/manage` | `views/pmt/timesheet/manage.vue` | `pmt:timesheet:manage` | PM 工时管理：筛选、批量审批、锁定/解锁、异常检查、导入导出 |
| （无路由） | `views/pmt/approval/index.vue` | — | 旧审批页，未挂路由（孤儿） |

### 核心状态机（工时单）

```
                 save(草稿)                 submit(本人)
   [新] ────────────────→ DRAFT ─────────────────────→ PENDING
                            ↑  ↑                          │
                 withdraw(本人)│                          ├── approve 全部节点 → APPROVED
                            │  └──────── REJECTED ←───────┤
                            └────── resubmit ─────────────┘（reject 回写状态可配 DRAFT/REJECTED）

独立维度：
  locked  : 0/1（仅 APPROVED 且 member.work_nature=SETTLE 可锁）
  settled : 0 未结算 / 1 全部结算 / 2 部分结算（按 item 汇总，仅统计 BILLABLE 明细）
  status  : DRAFT / PENDING / APPROVED / REJECTED（审批语义，不因锁定/结算而改变）
```

## 3.2 跨模块数据流链路（长链路）

### 链路 1：周工时 → 审批 → 锁定 → 结算（主链路，完全跑通）

```
① 人员准备
   pmt_employee(jobNumber,userId) + pmt_user(employeeId,employeeNo)
   pmt_project_member(projectId,userId/employeeId,workNature=SETTLE/NON_SETTLE)
   pmt_project_member_period(workloadRatio, 计划/实际起止)
        │
② 填报（/pmt/my-timesheet 或 /m/timesheet）
   GET  /timesheets/week-defaults        → 项目列表 + 每日默认小时(可用8h-请假 × 占比，超额等比缩放)
   GET  /timesheets/current?weekStartDate→ 已有工时单
   POST /timesheets/save                 → 按项目拆单：pmt_timesheet + pmt_timesheet_item
                                           + 异常检测 pmt_timesheet_anomaly
        │
③ 提交
   POST /timesheets/submit-week 或 /{id}/submit
   - 校验：本人、DRAFT/REJECTED、周范围、工时不足原因
   - status=PENDING；submit_time
   - ApprovalInstanceService.startApproval("TIMESHEET", timesheetId, …)
        │
④ 流程路由
   pmt_approval_business_type(TIMESHEET,status=1)
   pmt_approval_flow_binding(business_type=TIMESHEET, scope=PROJECT/GLOBAL, enabled=1)
        │ ORDER BY priority DESC, PROJECT>DEPT>ORG>GLOBAL
   pmt_approval_flow(status=1,isPublished=1) + pmt_approval_node
        │ 若 flow.pmApproverEnabled=1 且申请人 PMT_PM 且对项目有显式授权
        │ → 整链替换为 node_order=0 "主管审批" (SPECIFIC_USER=pmApproverUserIds)
   pmt_approval_instance(RUNNING) + pmt_approval_instance_node(PENDING)
        │
⑤ 审批
   GET  /timesheets/pending-approval  → 当前人待审（按最小 PENDING node_order + 审批人类型）
   POST /timesheets/{id}/approve      → 节点 APPROVED
        ├─ OR：同组其他 PENDING → SKIPPED
        ├─ AND：全部 APPROVED 才推进
        └─ 无下一节点 → instance APPROVED；timesheet.status=APPROVED；自动消除异常
   POST /timesheets/{id}/reject       → 节点 REJECTED；同组 SKIPPED；instance REJECTED；
                                         timesheet.status=节点 rejectStatus(默认 REJECTED)
        │
⑥ 锁定（PM/工时管理）
   POST /timesheets/batch-lock
   条件：status=APPROVED + member.work_nature=SETTLE + 未结算
   结果：pmt_timesheet.locked=1（status 仍 APPROVED）
        │
⑦ 结算（财务/PM）
   POST /settlements/batches/create-and-settle 或 /timesheets/batch-settle
   条件：locked=1 + 未结算 + member.work_nature=SETTLE
   结果：
     pmt_timesheet_item.settlement_status='SETTLED'（按天）
     pmt_timesheet.settled = 0/1/2（item 汇总，仅 BILLABLE）
     pmt_timesheet.settlement_batch_id/no/time
     pmt_settlement_batch.total_work_days/total_amount 重算
        │
⑧ 反哺
   结算统计 / 看板 / 执行状态 / 批次列表
```

**关键数字与口径**
- 工时单位：小时；前端步长 0.5；后端保存时保留 1 位小数并限制 0–8，但**不强制**必须是 0.5 的倍数。
- 工天 = 小时 / 8，保留 2 位。
- 标准周工时 = 工作日（考勤日历 dayType=1/4，缺省周一至周五）× 8。
- 默认工时 = `(8 - 当日请假小时) × 投入占比%`，同日多项目合计超上限则等比缩放。
- 单项目单日 ≤8h；同日所有项目合计 ≤8h。
- 结算只统计 `work_nature='BILLABLE'` 的 item（与结算动作标记所有明细的行为存在口径差，见 3.5 #2）。

### 链路 2：工时计划导入 → 项目成员/投入段 → 默认工时 → 执行状态

```
Excel（工号/姓名/项目角色/项目名称/工时性质/周列...）
   │ POST /timesheet-budget/import
   ▼
解析表头周列 → 行校验（工号/项目/工时性质）
   │
   ├─ 匹配 user(employee_no) 或 employee(job_number)
   ├─ 匹配 project(project_name)
   ├─ upsert pmt_timesheet_budget（employee_no+project_code+week_start_date+version）
   ├─ 物理删除同 version+project 的旧预算
   └─ 聚合员工+项目 → buildSegments（连续周合并投入段）
        └─ syncProjectMember：新增/更新 pmt_project_member（role/workNature/estimatedWorkDays）
           + pmt_project_member_period（plannedJoin/Leave=连续预算段起止，workloadRatio 默认 100%，estimatedWorkDays=段内预算小时/8）
   ▼
我的工时 GET /week-defaults → 读取活跃投入段 → 计算默认小时
   ▼
工时填报 → 实际工时
   ▼
工时执行状态 GET /timesheet-execution/list
   预算（pmt_timesheet_budget.planned_hours）
   + 实际（APPROVED 工时按周汇总）
   + 加班（APPROVED 加班按周）
   + 请假（APPROVED 请假按天折算）
   + 未审批状态（DRAFT/PENDING/REJECTED）
   → 员工×项目×周矩阵
```

> 注意：预算导入会把"看不到的 Excel 行"变成项目成员；这既是便利也是风险（错误 Excel 可能批量污染成员/投入段）。导入前建议在测试库验证。

### 链路 3：HR 同步 → 基础数据 → 工时校验/异常

```
HR 表（同库或 hr 数据源）：
  hr_org / hr_employee / hr_overtime_request / hr_leave_request / hr_attendance_calendar
        │ 手动：POST /base/{org|employees|overtime|leave|attendance-calendar}/sync
        │ 定时：HrDataSyncSchedule（仅 pmt.hr.enabled=true 注册）
        ▼
  pmt_org          （按 org_code upsert；HR 缺失逻辑删除）
  pmt_employee     （按 job_number upsert；缺失逻辑删除）
  pmt_overtime_request / pmt_leave_request / pmt_attendance_calendar
                   （DELETE 全表 + INSERT SELECT，全量物理替换）
        ▼
  工时规则：
   - 考勤日历 → 标准工时、非工作日、默认可用小时
   - 请假 → 默认工时扣减、LEAVE_CONFLICT 异常
   - 加班 → 执行状态周列、看板高工时员工、我的加班
        ▼
  工时单/异常/报表
```

**风险**：加班/请假/考勤为"全量物理替换"，会覆盖 PMT 本地手工修改；同步期间若有并发写入，可能丢失数据；ID 直接复用 HR 主键，需保证不与本地手工数据冲突。

### 链路 4：项目成员 → 自动建用户 → 角色 → 登录填报

```

   │ 员工 employee.userId 为空
   ▼

   用户名=工号；BCrypt(随机10位强密码)；need_change_password=1；initial_password=明文
   pmt_user 插入 → 分配 PMT_EMPLOYEE → pmt_employee.user_id 回填
   ▼
员工用 工号+初始密码 登录 → 强制改密 → 我的工时
```

**风险**：初始密码明文存 `pmt_user.initial_password` 且写入应用日志（`log.info("自动创建用户[{}]，初始密码：{}")`）；管理员可在用户列表看到"初始密码"列。生产环境应改为一次性重置链接或至少加密/脱敏。

### 链路 5（未闭环）：客户 → 合同 → 里程碑 → 发票 → 回款 → 成本

```
pmt_customer → pmt_project → pmt_contract → pmt_contract_line
                                   │
                                   ├→ pmt_payment_unit → pmt_milestone
                                   ├→ pmt_invoice → pmt_invoice_line
                                   ├→ pmt_payment_receipt → line
```

## 3.3 权限链路总览

```
[1] 登录
    AuthController.login → UserServiceImpl.login

        │
[3] 接口
    @PreAuthorize("@permissionChecker.hasPermission('pmt:x:y')")
      - userId=1 或 ROLE PMT_ADMIN → true
      - 精确匹配 / 单层通配 pmt:x:*

        │
[5] 前端页面
    router.beforeEach
      - requiresAuth → token

        │
[6] 前端菜单/按钮

      - SUPER_ADMIN/PMT_ADMIN → true

```

**常见越权/漏权点**

| 现象 | 根因 | 影响 |
|---|---|---|
| 非 admin 看不到项目 | 项目可见性只认显式授权，新项目默认无人可见 | 工时/结算/看板数据为空 |
| 菜单能进但接口 403 | 路由权限码与接口权限码不一致（如 manpower、logs、approval） | 页面空白/报错 |
| 有按钮但保存 403 | 前端 `usePagePerms` 自动补 `:view` 或通配判断与后端不一致 | 操作失败 |
| PM 看不到某个项目全员工时 | 严格数据域只认显式项目授权，且不认全局 0 | 审批/管理列表缺失 |
| 审批人收不到待办 | 流程未绑定、审批人类型不支持、或节点审批人不匹配 | 工时卡在 PENDING |

## 3.4 状态机汇总

| 对象 | 状态 | 迁移 | 触发 |
|---|---|---|---|
| 工时单 `status` | DRAFT / PENDING / APPROVED / REJECTED | DRAFT→PENDING；PENDING→APPROVED/REJECTED；PENDING→DRAFT（撤回）；REJECTED→PENDING（重提） | 保存/提交/审批/驳回/撤回 |
| 工时单 `locked` | 0 / 1 | 0→1（APPROVED+SETTLE+未结算）；1→0（未结算） | 批量锁定/解锁 |
| 工时单 `settled` | 0 / 1 / 2 | 0→2/1（按 item 结算）；1/2→0（取消结算） | 结算/取消 |
| 工时明细 `settlement_status` | UNSETTLED / SETTLED | 双向 | 结算/取消 |
| 异常 `status` | OPEN / RESOLVED | OPEN→RESOLVED | 人工消除/审批通过/工时达标 |
| 审批实例 `status` | RUNNING / APPROVED / REJECTED / CANCELED | RUNNING→APPROVED/REJECTED/CANCELED | 审批完成/驳回/撤回 |
| 审批实例节点 `status` | PENDING / APPROVED / REJECTED / SKIPPED | PENDING→APPROVED/REJECTED/SKIPPED | 审批/驳回/或签跳过 |
| 结算批次 `batchStatus` | DRAFT / SETTLED | DRAFT→SETTLED | 创建并结算/按月结算 |
| 用户 `status` | 0 禁用 / 1 启用 | 双向 | 管理员启停 |
| 角色/权限/字典/区域 `status` | 0/1 | 双向 | 管理员维护 |

## 3.6 建议的下一步验证清单

> 静态分析无法替代运行验证；以下按优先级排列。

1. **环境与数据**：拿到生产/测试库 DDL、初始化 SQL、真实账号（admin/PM/财务/成员/员工各一），确认表索引、唯一键、初始权限。
2. **主链路冒烟**：成员填报 → 提交 → 审批（或签/会签/PM 主管链）→ 驳回重提 → 撤回 → 锁定 → 结算 → 取消结算，逐状态核对 `pmt_timesheet / item / instance / batch`。
3. **权限矩阵回归**：5 个角色 × 12 个菜单 × 关键按钮，重点验证 2.9/3.5 中的权限码不一致项。
4. **数据域验证**：新项目默认不可见；给用户勾选"项目内所有成员"/"全部项目"；验证工时管理/审批严格域是否只认具体项目。
5. **财务页面联调**：合同/发票/回款/成本字段契约；若不打算上线，建议从路由和菜单彻底移除。
6. **HR 同步演练**：在测试库开启 `pmt.hr.enabled=true`，分别执行组织/员工/加班/请假/考勤同步，验证全量替换、逻辑删除、定时任务（尤其 leave）。
7. **安全核查**：JWT 密钥、初始密码明文、退出吊销、验证码、CORS、日志脱敏、详情接口越权。
8. **性能核查**：工时审批/管理 SQL 含多 EXISTS/OR 双数据域，已在代码中关闭 COUNT 优化；需在真实数据量下压测列表与导出。

## 结语：一句话判断

**PMT 是一套"以周工时审批 + 按天结算"为核心的轻量项目人天结算系统**，主链路完整、权限/数据域设计有想法；但财务域未上线、部分审批人类型未实现、若干权限码与页面字段不一致，属于"核心可用、外围半成品"的状态。上线前应优先修复 3.5 中的 P0/P1 项，并以"项目成员 → 周工时 → 审批 → 锁定 → 结算"作为唯一验收主线。
